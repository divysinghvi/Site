# Deviations from the plan

Append-only. One line per deviation: `- <area>: <what> — <why>`.

- repo: the Go module lives at the repository root (`module divy.dev`, entry `cmd/api/main.go`, packages under `internal/`) instead of the brief's `api/` + `collector/` directories — `docs/drafts/vercel-adaptation.md` (Vercel's Go preset needs a root `go.mod` and must not see a top-level `api/` functions directory); the collector is `internal/collector`.
- repo: `go.mod` says `go 1.24.0` (what `go mod tidy` rewrites `go 1.24` to, because the pinned dependencies declare `go 1.24.0`; no `toolchain` line) and pins `modernc.org/sqlite v1.46.1` and `prometheus/client_golang v1.23.2`, not the latest releases — newer versions declare `go 1.25`, which the build environment cannot run; the pins are the newest Go 1.24-compatible releases.
- repo: `divy schemagen` reads Go doc comments from `internal/model` relative to the working directory (falls back to schemas without descriptions elsewhere) — the generated files are byte-stable only when run from the repository root, which the Makefile guarantees.
- content: postmortem HTML is sanitized with bluemonday's UGC policy plus heading `id`, task-list `input[type=checkbox]` and table `align` attributes; goldmark's own raw-HTML stripping is kept on — one extra pure-Go dependency, same policy the draft named.
- content: `content.Options.CheckExpr` is a hook for the PromQL parser (rules `panels.expr`/`alerts.rulefmt` expression checks) — the parser lands with the PromQL package; until it is wired those rules only reject empty expressions.
- content: rule `alerts.rulefmt` is a structural check (names, durations, `{{ $value }}`/`{{ $labels.x }}` templates) instead of `prometheus/model/rulefmt` — avoiding the Prometheus module dependency; `promtool check rules` in the Makefile covers the rest.
- contract: API `Cache-Control` values carry an explicit `s-maxage` equal to `max-age` (`public, max-age=60, s-maxage=60`) — Vercel's CDN caches on `s-maxage`; clients see the contract's `max-age`.
- contract: the server never emits `X-Divy-Trace-Id` until the OTel package lands (no fake ids); the middleware slot is `server.Hooks.Outer`.
- contract: security headers (nosniff, Referrer-Policy, X-Frame-Options, Permissions-Policy) are set by the Go binary — there is no Caddy on Vercel; HSTS is Vercel's.
- storage: the series index is queried from SQL per request instead of an in-memory cache maintained by the writer — several serverless instances share one Turso database, so an in-process cache would go stale; the series table is ≤ ~100 rows.
- storage: `divy backup` (`VACUUM INTO`) is not implemented — no file database exists on Vercel; Turso keeps its own backups.
- storage: `divy migrate --status` is accepted but the command always prints the status table (there is no other output).
- web: the waterfall renders one row per span (Jaeger layout, DFS order, children sorted by start then id, collapsible subtrees) instead of packing non-overlapping siblings onto shared rows (content §C.3.6) — packing breaks parent→children adjacency in the tree; overlapping spans still land on parallel rows, which is what the brief asks for.
- web: `gen:types` is `node scripts/gen-types.mjs` (the json-schema-to-typescript API) rather than the `json2ts` CLI one-liner — the CLI cannot take a multi-line banner; the script also pins `additionalProperties:false` and `strictIndexSignatures` so no index signatures leak into the generated types.
- web: the site origin for absolute og:/canonical URLs comes from `PUBLIC_SITE_ORIGIN` and, when unset, from the origin the API put into the postmortems' `og_image` URLs (`SITE_ORIGIN` on the Go side) — one knob instead of two that must agree; `API_BASE` stays the build-time API address.
- web: TypeScript is pinned to 6.0.3 and @playwright/test to 1.56.1 — svelte-check 4.7.6 peers `^5 || ^6` (TS 7 is out), and 1.56.1 is the release whose Chromium build (1194) is preinstalled in the build environment.
- promql: the PromQL default lookback is 26h (`QUERY_LOOKBACK_DELTA`, `promql.DefaultLookback`), not the 2h of promql.md P3 — review finding protocol-02 (daily-gridded counters).
- promql: `/api/v1/label/{name}/values` accepts any non-empty valid-UTF-8 name (`1bad` → 200 `[]`; invalid UTF-8 → 400 `invalid label name`) — review finding protocol-03 (Prometheus 3 UTF-8 name validation).
- promql: `{target="pypi"} + {target="pypi"}` reports Prometheus' right-hand duplicate error (`found duplicate series for the match group … on the right hand-side …`, later series printed first), not the `multiple matches for labels` text promql.md E30/P.7.3 claim — the Prometheus 3.14 engine checks the right side first; the `multiple matches` error is raised when only the left side repeats a signature.
- promql: the optional `time`/`start`/`end` parameters of query, series, labels and label values fail as `invalid parameter "time": invalid time value for 'time': cannot parse "x" to a valid timestamp` (promql.md H6 omits the middle clause) — that is what Prometheus 3.14's parseTimeParam produces; query_range's required start/end keep the short form.
- promql: `rate(pypi_downloads_total[2d]) * 86400` over two daily samples yields 29.999999999999996, not the 30 of promql.md P.7.3 — the float operations are applied in Prometheus' order (`Δ × factor`, then `× 86400`); the tests pin the real value.
- promql: the Prometheus oracle module (`api/tools/promql-oracle`, note P7) is not built — Prometheus v0.314.0 requires Go 1.25 and the sandbox has 1.24; every test expectation was recomputed by hand from the Prometheus 3.14 source instead.
- promql: `/api/v1/query` and friends set a weak ETag and answer 304 themselves; the server-side response cache and `X-Cache` (contract K.3.2) belong to the middleware lane.
- metrics: `divy_collector_last_success_timestamp_seconds` is read from `collector_runs` at scrape time (correct across serverless instances) rather than kept as an in-process GaugeVec seeded at startup; `divy_collector_runs_total` and `divy_collector_run_duration_seconds` are in-process and reset on a cold start, as the drafts say.
- metrics: `/metrics` hides a stored series after `max(3 × collector cadence, 15m)` (storage §S.2.6, contract K-I2) and exposes only catalogue families; a series outside the catalogue stays queryable through the API.
- metrics: `promtool check metrics --extended` from promql.md §P.9 is not a flag of promtool 3.5; `make promtool-check` runs `promtool check metrics` and `promtool check rules content/alerts.yaml`.
- content: `content/spans.yaml` lines 200 and 418 quoted (`fix: "…, alert hygiene"`, `name: "5,000+ active users"`) — a bare `, ` inside a YAML flow mapping split the values and the schema rejected them; no wording changed.
- collector: `/api/collect` runs only the collectors whose last successful run is older than their interval (minus `min(interval/10, 1m)`), reporting the rest as `skipped: not due`; `?force=1` runs every collector and `divy collect --once` always does — the endpoint is called every 5 minutes by the GitHub Actions schedule while GitHub (15m), PyPI (60m), manual (15m) and retention (60m) keep the cadences of the env table; uptime (5m) runs every round.
- collector: counter backfills write only the grid points that are missing or changed (one read of the series per run) instead of upserting the whole window every run — a hosted database (Turso) meters row writes; the samples are identical.
- collector: a run's sample writes go through one `store.Write` transaction (`collector.Batch`) so `store.Generation()` is not bumped by them (only `EnsureSeries`, `WriteProbeResults` and `DeleteSeriesWhere` bump it) — the store owner should bump the generation inside `Write` or export a `Bump`; nothing reads `Generation()` yet.
- collector: uptime probes follow at most 5 redirects (the draft said Go's default 10) and count a final 2xx or 3xx as up when a target lists no `expected_status` (the draft defaulted to `[200]`); an explicit `expected_status` list is exact — the task brief fixed both; `/api/content/uptime` still displays the content default `[200]` for targets without an explicit list.
- collector: an uptime incident is a run of at least two consecutive failed probes (the draft counted every failed run); a single failed probe stays visible in the day's `up_ratio` but is not listed as an incident.
- collector: a probe cut short by the collection round's budget (not by its own timeout) records nothing — a gap — instead of a red timeout caused by our own deadline.
- collector: the merged-PR scan starts with one unbounded search (`is:pr is:merged author:<login>`) and splits into calendar-year windows (then halves) only when `issueCount` exceeds the 1000-result cap — fewer requests than the draft's per-year windows for a small history; the cursor and the events collected so far live in `collector_state` (`github.prs`), so a scan resumes across rounds and instances.
- collector: `github_stars` is written for every public non-fork repository including archived and zero-star ones (panels filter with `> 0`); `pypi_package_info` keeps exactly one version series per package (older versions deleted in the same run).
- server: `/favicon.ico` answers a cacheable 404 (`max-age=86400`) pointing at `/favicon.svg` — review coverage-17: a committed sparkline-shaped `.ico` would be a static sparkline; the SVG is the only favicon.
- server: `/readyz` `checks.db.storage` (`file` | `libsql` | `ephemeral`) and `/api/uptime` targets' `note` are additive model fields (`ReadyzDB.Storage`, `HeartbeatTarget.Note`); `schema/` regenerated, `web/src/lib/api/types.gen.ts` must be regenerated by the web lane (`make web-gen`).
- web: the dashboard grid is a custom pointer-based implementation (web/src/lib/panels/grid.ts + DashboardGrid.svelte: percentage placement, collision push-down, upward compaction, keyboard move/resize via the panel menu) instead of gridstack 13 (repo §R.7.3) — gridstack mutates the DOM it is given, which fights Svelte 5's keyed rendering, and the collision/compaction rules needed are ~60 lines; no extra 24 kB dependency.
- web: the Prometheus client helpers live in web/src/lib/panels/prom.ts (repo draft: lib/api/prom.ts) and narrow the four `resultType` shapes there — web/src/lib/api/types.gen.ts predates the Prom* entries in schema/index.schema.json (regenerate with `make gen` and switch the local `PromResultType` alias to the import once it carries them).
- web: Explore is addressed as `/explore?ds=prom&expr=…&from=…&to=…[&instant=1]` with Grafana-style relative times (`now-7d`/`now`) or unix seconds, not the draft's `range=` parameter — the W2 task specifies from/to; panel Explore links use the preset's relative form so the window follows "now".
- web: the dashboard auto-refresh toggle re-queries every 30 s (the W2 task's value), not `dashboard.refresh: 60s` from content/panels.yaml — the file's value is still served; switch the constant REFRESH_MS in web/src/routes/(site)/dashboard/+page.svelte to read it if the two should agree.
- web: postmortem pages take `og:image` from the API's `og_image` field (`<origin>/og/postmortems/<id>.png`, contract K.1.5) rather than a hard-coded `/og/<id>.png` — one source of truth for the OG route, which the OG lane owns; the tag is emitted before the endpoint exists.
- web: postmortems and uptime targets link their span as `/trace/career?span=<id>` (the W3 task's form) and the trace viewer consumes `?span=` into the existing `#span=` state on load; the API's `span_url` (`/#trace?span=<id>`) keeps working unchanged.
- web: the SEV1–SEV4 definitions shown in the severity tooltip are UI vocabulary in `web/src/lib/postmortem/index.ts` (content §C.5.1's fixed table) — the API serves only the level; every fact about an incident still comes from `/api/content/postmortems*`.
- web: the uptime page renders the 90-day daily heartbeat only (`/api/uptime`), not the draft's hourly cells above 1024 px (K-I9's 7-day `bucket=1h` view) — the W3 task asks for one cell per day; `api.uptime.heartbeats(7, '1h')` is available when a 7-day view is added.
- web: the postmortem table of contents collapses into a `<details>` bar below 900 px (not only ≤ 640 px) — a sticky sidebar next to a 78ch monospace column does not fit between 640 and 900 px.
- logql: bytes literals (`512KB`, `3MiB`) are accepted in numeric label filters (logql.md §L.1.7 listed them as unsupported) — the task asked for duration/bytes/number parsing and `go-humanize` was already an indirect dependency; `| name > 3MiB` compares both sides in bytes.
- logql: `rate({service="gradr"}[30d])` over one line renders `0.00000038580246913580245` (logql.md L.7.2 #17 wrote `0.0000003858024691358025`) — `strconv.FormatFloat(1/2592000, 'f', -1, 64)` is the shortest round-trip form, the same call Loki makes; the tests pin Go's value.
- logql: logql.md L.7.2 #18 and #19 print `1757030400` for 2026-09-05T00:00:00Z, which is 2025-09-05 — the tests pin `1788566400`.
- logql: the numeric-vs-string message is `numeric comparison needs a number, duration or bytes literal, got string` (logql.md said `… a number or duration …`) — bytes literals are accepted now.
- logql: a nested vector aggregation (`sum(sum(…))`) fails with `syntax error: unexpected IDENTIFIER "sum", expecting count_over_time or rate` — the draft grammar only allows a range aggregation inside an aggregation; the error names what is expected.
- logql: the weak ETag of `/loki/api/v1/query_range` and `/query` hashes `resultType` + `result` rather than the whole body — `stats.summary.execTime` changes on every evaluation, so a body hash would never let `If-None-Match` answer 304.
- logql: the 5000-entry cap on `limit` applies to log queries only (a metric query with `limit=6000` succeeds) — Loki validates the per-query entry limit in the log path; the draft's "limit ignored for metric queries" is kept literal.
- model: the Loki success shapes are one Go type `LokiQueryResult` (`resultType` streams | matrix | vector) instead of the contract's separate `LokiQueryRangeResult` / `LokiQueryResult` names — one type per shape keeps the generated TypeScript union small; `schema/` regenerated, `web/src/lib/api/types.gen.ts` must be regenerated by the web lane.
- server: three env knobs beyond the Vercel-adaptation table — `OTEL_TRACING` (on|off, default on), `RATE_LIMIT_GLOBAL_RPS`/`RATE_LIMIT_GLOBAL_BURST` (the bucket shared by /healthz, /readyz, /metrics; defaults 50/200) and `TRUST_PROXY_HEADERS` (on|off, default on when `VERCEL` is set) — the middlewares had these settings with no way to reach them from the environment; `RATE_LIMIT_RPS=0|off` turns the per-client bucket off.
- server: the OTel provider is built in `cmd/api` before the router (it needs the store, the router needs the provider), so the `divy_otel_*` counters are attached afterwards through `trace.Provider.SetMetrics` from `server.New` — one registry behind /metrics, no second registry in the provider.
- collector/github: a transport error whose context is already cancelled is returned as `github: request: <ctx.Err()>` with the context error in the chain (`%w`) instead of the redacted transport message — `fetchContributions` cancels its sibling windows after a real failure and must recognise the cancellations it caused (`errors.Is`) to report the 401/GraphQL error; the flaky `TestErrors` came from this.
- deploy: the Docker build stage is `node:22-bookworm` with the Go toolchain copied from `golang:1.24-bookworm` (one stage runs both passes) rather than two separate toolchain stages — the prerender pass needs the pass-1 binary running while npm builds, which only works inside one `RUN`.
- deploy: the image ships `content/` at `/content` (`DIVY_CONTENT_DIR=/content`) instead of relying on the binary's extraction of the embedded copy to `/tmp` — distroless static has no guaranteed writable `/tmp` for the non-root user; the embedded copy stays the fallback.
- deploy: `compose.yaml` uses `include:` (Docker Compose ≥ 2.20) to pull in `deploy/docker-compose.yml`, whose paths (`context: ..`, `env_file: ../.env`) are relative to `deploy/` — validated with `docker compose config` (v5.1.1, no daemon needed) in the build sandbox; the image itself could not be built there (no daemon), CI's docker job does that.
- ci: golangci-lint is installed with its official install script pinned to v2.5.0 (the version the build sandbox verified against `.golangci.yml`) rather than the golangci-lint GitHub action — `make lint` runs it the same way locally and in CI.
- ci: `collect.yml` fails only when the HTTP call fails (401, 5xx, timeout); collectors that fail inside a 200 summary are `::warning` annotations — a pypistats or GitHub hiccup every 5 minutes would otherwise paint the Actions tab red and `/readyz` already reports collector freshness.
- docs: `deploy/README.md` is a pointer to `docs/deploy.md` (the brief's Caddyfile, systemd unit and Hetzner script do not exist — Vercel adaptation).
- web: the Konami `grafana2017` theme persists in `sessionStorage` (`divy.theme.session`) and wins over the `localStorage` dark/light choice before first paint; toggling dark/light or entering the code again leaves it — the task asked for a session-scoped theme, the earlier store persisted every theme to localStorage.
- web: the alert engine (`$lib/alerts/engine.svelte.ts`) is started once from the root layout and polls `/api/v1/query` every 15 s (`?alerts_fast=1` on the first page loaded: 1 s and every `for` ÷ 10, the Playwright hook); silences live in `sessionStorage` (`divy.alerts.silences`) — the brief's "silence for the session".
- web: the prerender's `handleMissingId` ignores `key=value` fragments (`/dashboard#panel=…` from content runbook URLs, `#layout=…`) — they are dashboard state read by the page, not element ids; every other missing fragment still fails the build.
- web: the toast region is `role="region" aria-label="Notifications" aria-live="polite"`, not `role="status"` — a permanent status landmark collided with the pages' own `role="status"` empty states in the tests and in screen-reader output.
- web: touch targets are forced to 44 px with `!important` under `(pointer: coarse)` (app.css) — component-scoped `.btn.small` sizes are more specific than the global rule; desktop keeps the dense 32 px controls.
- web: `--fg-dim` is #939ba4 (dark) / #5f6770 (light) instead of #7b838d / #6f7780, `.btn-primary` uses a deeper `--primary` blue (#3b6fd6) rather than `--blue`, severity badges tint 10 % over `--bg` — axe `color-contrast` (serious) on the 11–13 px labels; the palette accents themselves are unchanged.
- web: `make web-e2e` / Lighthouse against a fresh binary need the rate limiter raised (`RATE_LIMIT_RPS=1000 RATE_LIMIT_BURST=5000`): a 4-worker Playwright run from one IP trips the 20 rps / burst 100 defaults (429s) — recorded in docs/lighthouse.md; the Makefile is the API lane's.
- web: postmortem task-list checkboxes get an `aria-label` from their item text after hydration (axe `label`, critical) — the API's sanitized HTML has no labels; the prerendered HTML is unchanged.
- content: oss.minikube children are the 6 merged PRs found in kubernetes/minikube git history (merge commits from divysinghvi/* branches + squash merges authored by Divy, all branches); the brief's "15+" was not substantiated by that repository alone — add other repositories' PRs to reach the real total. oss.kubeflow removed on request. Root children now render in file order (API + viewer) so the oss subtree can sit last.
